# 画布图像工具：裁剪 / 拉伸（设计说明）

> 需求：给系统增加两个简单图像工具——① 裁剪图片尺寸；② 直接拉伸更改图片尺寸。
> 关键要求：**全部在画布上直接操作**，不让用户手填参数。
> 日期：2026-10-27
> 结论：两个工具都做成画布交互模式，纯本地 Canvas 处理，不经过 AI 接口。

## 1. 需求与交互结论

| 工具 | 交互 | 结果 |
| --- | --- | --- |
| 裁剪 | 点底部工具栏「裁剪」→ 选中图层上出现可拖动 / 缩放的裁剪框（框外压暗）→ 拖动调整 → 点「应用裁剪」或按 Enter | 只保留框内区域，像素 1:1 不缩放；结果替换当前图层，并保持裁剪区域原来的画布位置 |
| 拉伸 | 点「拉伸」→ 直接拖拽图层四角 / 四边的控制柄改变显示尺寸 → 点「应用拉伸」或按 Enter | 把拖拽后的显示尺寸固化成真实图片像素（非等比缩放，允许变形）；结果替换当前图层 |

两个模式都支持 `Esc` / 「取消」退出；取消拉伸会还原拖拽产生的临时缩放。

设计要点：

1. **画布优先**：不再有右侧「图像工具」参数面板；工具入口与画笔 / 框选 / 套索并列在画布底部工具栏；
2. **所见即所得**：裁剪框外压暗、拉伸时实时显示「输出尺寸 W × H px」，比例变化会提示「会变形」；
3. **纯本地处理**：不调用 `/v1/images/*`、不需要 API Key、不消耗额度；
4. **替换当前图层**：与「改图片尺寸」的直觉一致；处理完成后仍可继续 AI 编辑、抠图、下载。

## 2. 裁剪模式

### 2.1 交互

- 进入条件：左侧图层列表 / 画布上选中一个图层；未选中时按钮禁用；
- 裁剪框：覆盖选中图层，默认等于整图；四角 + 四边共 8 个控制柄；禁止旋转、禁止翻转；框外区域用四条半透明矩形压暗；
- 点击框内拖动可整体平移裁剪框；裁剪框允许超出图片，应用时会自动与图片范围求交；
- 底部浮条实时显示「裁剪尺寸 W × H px」；与图片无交集或区域过小时禁用「应用裁剪」；
- 键盘：`Enter` 应用、`Esc` 取消。

### 2.2 像素换算

裁剪框是**画布场景坐标**，而裁剪要做在**图层原始像素**上：

1. 先把裁剪框与图层包围盒求交；
2. 用图层 `calcTransformMatrix()` 求逆，把交集的四个角映射回图层局部坐标（Fabric 的矩阵以对象中心为原点，需再加回 `width/2`、`height/2`）；
3. 取局部坐标的最小 / 最大包围盒并夹到 `[0, width] × [0, height]`，得到裁剪矩形。

这样即使图层在画布上被缩放（`scaleX/scaleY ≠ 1`）也能得到正确的原图像素矩形。

裁剪结果替换原图层时：

- 新图层 `x/y` = 裁剪框交集在画布上的左上角，保证裁剪后内容仍出现在原来的位置；
- 图层原有的显示缩放、旋转保持不变，因此视觉大小与裁剪前完全一致。

**限制**：裁剪暂不支持旋转图层与翻转图层（场景坐标的轴对齐矩形在旋转/翻转后不再对应图片的轴对齐矩形）。选中这类图层进入裁剪模式时，浮条会给出提示并禁用「应用裁剪」。

## 3. 拉伸模式

### 3.1 交互

- 进入条件同上；
- 只允许操作当前选中的图层，其它图层不可选中；
- 拖拽四角 / 四边控制柄即可非等比缩放（默认行为，允许变形）；禁止拖成翻转；
- 底部浮条实时显示：
  - 「输出尺寸 W × H px」（= 图层原始像素 × 当前缩放）；
  - 「（比例已改变，会变形）」提示；
  - 放大 ≥ 4×、或输出像素很大时的提示；
  - 超出单边 / 总像素上限时显示红色错误并禁用应用；
- 未改变尺寸时「应用拉伸」禁用；
- 键盘：`Enter` 应用、`Esc` 取消；取消时恢复进入模式前的 `left/top/scaleX/scaleY`。

### 3.2 固化像素

应用时：

```
目标像素 = round(图层原始宽高 × 当前缩放)
```

用 Canvas 把原图重采样到目标尺寸（PNG，保留透明通道），替换图层并把 `scaleX/scaleY` 归位为 1、`x/y` 保持当前值。因为「原始尺寸 × 缩放」等于拖拽后的显示尺寸，所以固化前后视觉大小和位置不变，但图片真实像素已经变成目标尺寸。

## 4. 实现

### 4.1 新增 `src/lib/canvasImageTools.js`

| 函数 | 作用 |
| --- | --- |
| `normalizeAngleDelta(angle)` | 角度归一化成 0°～180°，判断图层是否被旋转 |
| `intersectBounds(a, b)` | 两个场景矩形求交 |
| `sceneBoundsToImageRect(layerObj, sceneBounds)` | 场景裁剪框 → 图层图片像素矩形（矩阵求逆，兼容缩放） |
| `computeStretchInfo(layerObj)` | 由当前缩放推导目标像素尺寸 + 校验结果 + 是否改变/变形 |

纯计算模块，可在 Node 中单测。

### 4.2 `src/components/CanvasEditor.jsx`

- `drawMode` 增加 `'crop' | 'stretch'`；
- 裁剪 effect：创建裁剪框 + 四条压暗矩形，绑定 `object:moving/scaling/modified` 实时更新尺寸与压暗层；点击空白处自动重新选中裁剪框；退出时清理全部叠加层；
- 拉伸 effect：只让当前图层可选中，绑定缩放事件实时计算目标尺寸；取消时还原原始变换，并用 `fabricCanvas.fire('object:modified')` 把还原同步回父组件；应用时把目标尺寸交给父组件；
- 底部工具栏新增「裁剪」「拉伸」两个图标按钮，以及模式浮条（尺寸 / 提示 / 取消 / 应用）；
- 键盘：裁剪 / 拉伸模式下屏蔽撤销、删除等快捷键，仅处理 Enter / Esc；
- 裁剪框与压暗层统一打 `isCanvasOverlay` 标记，避免被当成遮罩区域、进入撤销快照或被 AI 遮罩逻辑收集；
- 开发模式下把 Fabric 实例挂到 `window.__fabricCanvasForTest`，供 E2E 使用（`import.meta.env.DEV` 守卫，生产构建移除）。

### 4.3 `src/App.jsx`

- `handleCropLayer({ layerId, rect, x, y })`：调用 `cropImageToDataUrl` 生成裁剪图，替换图层并保持画布位置；
- `handleStretchLayer({ layerId, width, height, x, y })`：调用 `resizeImageToDataUrl` 重采样，替换图层并把显示缩放归位为 1；
- AI 遮罩相关过滤新增 `!obj.isCanvasOverlay`，避免工具叠加层被当成遮罩。

### 4.4 移除

- 删除上一版的手填参数面板 `src/components/ImageToolsPanel.jsx`；
- `ControlPanel.jsx` 移除图像工具区块及 4 个相关 props；
- `src/lib/imageTools.js` 保留裁剪 / 拉伸的 Canvas 处理与校验（纯函数仍被复用）。

## 6. 验证记录（2026-10-27）

环境：Windows + Vite dev server + 无头 Edge（`--virtual-time-budget`，窗口 1600×1000）。构建时把 `TEMP/TMP` 指向工作区临时目录（当前 harness 沙箱对系统 TEMP 有 ACL 限制，直接构建会在 esbuild 删除临时文件时 `Access is denied`，与代码无关）。

- `npm run build`：通过；
- ESLint 新增文件（`canvasImageTools.js` / `imageTools.js`）：0 error / 0 warning；`CanvasEditor.jsx` / `App.jsx` 剩余报错均为仓库原有问题（未使用变量、React Compiler immutability 规则），新增代码区域无新增报错；
- `canvasImageTools` 纯函数单测（Node + esbuild 打包）：**10/10 通过**（角度归一化、矩形求交、整图/中心区域/缩放 2×/越界夹取的像素换算、拉伸尺寸与上限校验）；
- 画布 E2E（真实上传 400×300 图片，真实鼠标事件拖拽控制柄）：**30/30 通过**，覆盖：
  - 右侧不再有手填参数面板、底部有裁剪 / 拉伸按钮；
  - 拉伸：显示原尺寸 → 拖拽右下角放大 → 实时尺寸变化 → 应用后图层像素尺寸变为拖拽尺寸、显示缩放归位 1、位置不变；
  - 裁剪：裁剪框与压暗层创建 → 拖拽右下角缩小 → 实时裁剪尺寸变化 → 应用后图层像素尺寸变为裁剪尺寸、位置仍在原裁剪区域；
  - `Esc` 取消裁剪不改变图片；取消拉伸恢复原显示缩放、再次进入尺寸恢复原值；
  - 两个模式退出后叠加层全部清理；全流程无页面 JS 错误。
- 说明：无头 Edge 下对 Fabric 画布 `getImageData` 读回全 0（截图正常），因此 E2E 改用 Fabric 实例的 `viewportTransform` 计算控制柄坐标；这是测试环境限制，不代表产品问题。

## 7. 未验证 / 后续可做

1. **裁剪范围仅作用于当前选中图层**：暂不支持「裁剪整个画布（所有图层）」，需要时可再加；
2. **旋转 / 翻转图层不支持裁剪**：会提示并禁用应用；
3. **图层级撤销**：裁剪 / 拉伸替换图层后不可撤销（与现有 AI 编辑替换一致）；需要保留原图时可先复制图层；
4. **裁剪框交互细节**：暂不支持比例锁定、裁剪框键盘微调、双击确定等；
5. **超大输出**：拉伸输出被限制在单边 ≤ 16384、总像素 ≤ 4000 万；不同浏览器 Canvas 上限略有差异，未逐浏览器实测；
6. **移动端触控**：未针对触摸屏做专项测试。
